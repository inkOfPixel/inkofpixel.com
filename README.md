# inkofpixel.com

The inkOfPixel website: plain HTML, CSS and JavaScript, generated by a small Node build script and served by Caddy.

No framework and no client-side runtime: the pages work without JavaScript, which only adds the ink animation, the cursor effects and the mobile menu.

## Develop

```sh
npm install
npm run dev     # http://localhost:4321, rebuilds on every change
npm run build   # writes the site to dist/
npm run images  # shrinks new images in static/assets (needs ffmpeg for GIFs)
```

`npm run build` also refreshes the privacy policy from iubenda and stores a copy in `content/legal/privacy.html`, so the site still builds offline (`SKIP_REMOTE=1 npm run build`).

## Where things are

| Path | What it holds |
| --- | --- |
| `content/static-pages/*.json` | Copy of the home, services, projects, blog and contacts pages, one entry per language |
| `content/projects/*.md`, `content/posts/*.md` | Case studies and blog posts, one `locales` entry per language |
| `content/settings/*.json` | Email, socials, company details shown in the footer |
| `static/` | Files copied as they are: images in `static/assets`, favicon |
| `src/templates/` | One file per page type, plus `layout.mjs` (header, menu, contact section, footer) |
| `src/assets/site.css`, `src/assets/site.js` | All the styles and all the scripts |
| `src/lib/site.mjs` | Languages, URL structure and interface labels |
| `src/build.mjs` | The build: reads the content, renders every page in every language |
| `scripts/optimize-images.mjs` | Resizes and recompresses images, turns animated GIFs into short videos, updates the references in `content/` |
| `server/` | The only server-side code: the contact form handler and the container entry point |

Pages exist in English (default, at `/`) and Italian (at `/it/`). The URLs match the previous Gatsby site.

## Deploy

The site ships as a Docker image (build stage on Node, then Caddy serving `dist/`) deployed with [Kamal](https://kamal-deploy.org) behind kamal-proxy.

```sh
docker build -t inkofpixel . && docker run --rm -p 8080:80 inkofpixel   # try the production image locally
kamal deploy                                                            # deploy to the server in config/deploy.yml
```

The `Deploy` GitHub Actions workflow runs `kamal deploy` on demand. It needs the `KAMAL_DEPLOY_SSH_PRIVATE_KEY`, `SMTP_USERNAME` and `SMTP_PASSWORD` repository secrets.

## Contact form

The form on the contacts page posts to `/api/contact`. In the container Caddy passes `/api/*` to a small Node process (`server/main.mjs`), which checks the message and forwards it by email over SMTP. Nothing is stored.

It is configured in `config/deploy.yml`: `CONTACT_TO`, `CONTACT_FROM`, `SMTP_HOST`, `SMTP_PORT`, plus the `SMTP_USERNAME` and `SMTP_PASSWORD` secrets (for AWS SES these are the "SMTP credentials", not the IAM keys). `CONTACT_FROM` must be a sender the SMTP provider accepts.

With `npm run dev` and no SMTP settings, submitted messages are printed in the terminal instead of being sent.

`Caddyfile` holds the server rules: clean URLs, redirects from old addresses, cache headers and the 404 pages.
